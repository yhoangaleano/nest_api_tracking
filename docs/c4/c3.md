# C3: Diagrama de componentes de la API

**Estado:** Aceptado
**Fecha:** 2025-11-18

## 1. Descripción

Este diagrama de nivel 3 (componentes) detalla la estructura interna del contenedor `API monolítica`.

Muestra los componentes principales dentro de la aplicación NestJS y cómo orquestan el flujo de peticiones síncronas, aplicando los principios de Arquitectura Limpia (ADR 001). Se enfoca en la separación de responsabilidades:

*   **Presentation (controlador):** Recibe peticiones HTTP.
*   **Application (casos de uso):** Orquesta la lógica de negocio.
*   **Infrastructure (adaptadores):** Implementa la interacción con la base de datos y el caché.
*   **Domain (entidades y puertos):** Define las reglas y las interfaces.

## 2. Diagrama

```mermaid
%%{ init : { "theme" : "default" } }%%
C4Component
    title "Diagrama de componentes (C3) de la API monolítica"

    Person(actor, "Usuario/Operador", "Cualquier actor que interactúa con la API")

    ContainerDb(postgres, "Base de datos", "PostgreSQL")
    ContainerDb(redis, "Caché", "Redis")

    System_Boundary(api, "API monolítica") {

        Component(controller, "Tracking controller", "NestJS Controller", "Maneja rutas, valida DTOs y llama a casos de uso.")
        
        Component(use_cases, "Casos de uso", "NestJS Services", "Contienen la lógica de la aplicación (ej. RegisterCheckpoint, GetTrackingHistory).")

        Component(domain, "Dominio", "Clases y Interfaces TS", "Define entidades (Unit), VOs y puertos (IUnitRepository, IUnitCache).")

        Component(pg_adapter, "Postgres repository", "NestJS Service", "Implementa IUnitRepository para interactuar con PostgreSQL.")
        
        Component(redis_adapter, "Redis cache", "NestJS Service", "Implementa IUnitCache para interactuar con Redis.")
    }

    %% --- Relaciones ---

    %% Flujo de la petición
    Rel(actor, controller, "Realiza petición", "JSON/HTTPS")
    Rel(controller, use_cases, "Usa")

    %% Dependencia de los casos de uso hacia el dominio
    Rel(use_cases, domain, "Depende de (puertos y entidades)")

    %% Implementación de los puertos por la infraestructura
    Rel(pg_adapter, domain, "Implementa puerto de repositorio")
    Rel(redis_adapter, domain, "Implementa puerto de caché")

    %% Interacción de la infraestructura con los sistemas externos
    Rel(pg_adapter, postgres, "Lee y escribe", "TypeORM")
    Rel(redis_adapter, redis, "Lee y escribe", "node-redis")
```
