# C2: Diagrama de contenedores del sistema

**Estado:** Aceptado
**Fecha:** 2025-11-12

## 1. Descripción

Este diagrama de nivel 2 (contenedores) hace "zoom" dentro de la caja negra del **Sistema de tracking logístico**. Muestra los principales componentes de software (contenedores) que interactúan para entregar la funcionalidad.

Visualiza la decisión clave de arquitectura (ADR 002) de separar las peticiones (API) del procesamiento (worker) mediante una cola de mensajes.

## 2. Diagrama (Mermaid)

```mermaid
%%{ init : { "theme" : "default" } }%%
C4Container
    title "Diagrama de contenedores (C2) del sistema de tracking"

    %% Actores externos (ahora como Person)
    Person(operador, "Operador logístico", "Escanea paquetes")
    Person(cliente, "Cliente", "Consulta su envío")
    Person(admin, "Administrador (backoffice)", "Monitorea la operación")

    %% Límite del sistema
    System_Boundary(tracking_system, "Sistema de tracking logístico") {

        Container(api, "API web (productor)", "NestJS / Docker", "Recibe peticiones HTTP, valida y encola.")
        Container(worker, "Worker (consumidor)", "NestJS / Docker", "Procesa mensajes, aplica lógica de negocio y persiste.")
        ContainerDb(db, "Base de datos", "MongoDB", "Almacena unidades y checkpoints embebidos (ADR 003).")
        ContainerQueue(queue, "Cola de mensajes", "RabbitMQ", "Buffer para garantizar la entrega de checkpoints (ADR 002).")
    }

    %% --- Relaciones ---

    %% 1. Personas -> API
    Rel(operador, api, "Envía checkpoint", "POST /checkpoints")
    Rel(cliente, api, "Consulta tracking", "GET /tracking/:id")
    Rel(admin, api, "Consulta estados", "GET /shipments")

    %% 2. Flujo asíncrono de escritura (ADR 002)
    Rel(api, queue, "Publica evento de checkpoint", "AMQP")
    Rel(worker, queue, "Consume evento de checkpoint", "AMQP")
    Rel(worker, db, "Escribe/actualiza unit y checkpoints", "Mongoose")

    %% 3. Flujo síncrono de lectura (ADR 005)
    Rel(api, db, "Lee historial y estados", "Mongoose (findOne)")
```
